================================================
4. VERDICT RULE
================================================

Allowed internal verdicts only:

GOOD
MODERATE
MIXED
CHALLENGING

Do not allow arbitrary values such as:
"Very strong agreement"
"Early signal"
"Worth watching"
"Positive"
"Neutral"

The final verdict must come from complete confluence, not from an LLM guess.

================================================
5. COMPLETE CONFLUENCE
================================================

Use all applicable validated evidence lanes, including where available:

- natal foundation
- main timing cycle
- Chara
- Yogini
- slow transit
- period-planet transit
- natural significator
- other validated calculation families

One lane must never overwrite the complete judgement.

A dasha/period change alone must NOT mean:
- improvement
- success
- relief
- GOOD verdict

Every material future checkpoint must recalculate the complete confluence.

================================================
6. FIX DUPLICATE FUTURE CHECKPOINTS
================================================

Current bug:
The sample contains duplicate dates such as February 2028 and December 2028.

Implementation:

raw_events = collect_all_timing_events()

Normalize every event to a canonical date key:
YYYY-MM or YYYY-MM-DD.

Group all events by that key.

Example:

December 2028:
- Chara changes
- Yogini changes

must become ONE checkpoint:

December 2028
- trigger: Chara change + Yogini change
- complete recalculation
- one final judgement

Never render separate rows for separate methods on the same date.

Then sort checkpoints chronologically.

================================================
7. REMOVE NON-MATERIAL CHECKPOINTS
================================================

After deduplication, keep a checkpoint when:

verdict changes
OR
a major evidence lane materially changes
OR
a meaningful timing phase starts/ends
OR
the engine identifies a genuine material change

Remove purely repetitive events.

Do not remove a checkpoint just because the final verdict remains the same if the underlying confluence materially changes.

================================================
8. BASELINE
================================================

Every area gets exactly one current baseline.

Example:

August 2026
Baseline · Mixed

Do not hard-code the date. Use the actual report/current chart date.

================================================
9. FIRST MATERIAL EASING
================================================

Never define first easing as merely:
"first dasha change"

Instead, find the first post-baseline checkpoint where:
- complete confluence materially improves
- multiple independent factors support the change
- no major cautionary factor cancels the improvement

If none exists:
"No clear material easing is established within the forecast horizon."

================================================
10. STRONG IMPROVEMENT
================================================

Strong improvement requires:
- complete confluence = GOOD
OR
- a predefined engine threshold supported by multiple independent methods

Never:
one positive transit = strong improvement
dasha change = strong improvement
one benefic planet = strong improvement

================================================
11. CUSTOMER-FACING TIMING
================================================

Timing is mandatory in every area.

It must answer:
1. What is happening now?
2. Until when?
3. First meaningful easing/change?
4. Stronger improvement window?
5. If no strong improvement exists, say so.

Example:

Timing:
"Pressure remains elevated through November 2027. The first meaningful easing appears around December 2027. A stronger supportive phase requires later timing and transit factors to align."

If the engine has no supported date:
"No single strong timing window is established by the available calculation."

Never invent a date.

================================================
12. ASTROLOGER-STYLE CONCLUSION
================================================

One paragraph per area, ideally 3–5 sentences.

Logical sequence:

CAUSE
-> CURRENT EFFECT
-> TIMING
-> WHAT CHANGES
-> PRACTICAL INTERPRETATION

The conclusion must be specific to that area.

Avoid generic text such as:
"neither a clear yes nor a clear no"
"do not force a big step"
"be patient"

unless the calculation actually supports it and it is contextualized.

Do not repeat the Timing paragraph word-for-word inside the conclusion.

- Chara

- confluence

Then code validates the LLM output and renders HTML.
